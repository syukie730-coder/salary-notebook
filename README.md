# 💰 お給料明細

**パシャッと撮って、かんたん記録。**

iPhone の縦画面を中心にした、夫専用の給与明細ノートです。撮影または写真選択 → 端末内で読み取り → 大きな数字を確認 → 「これで保存」の流れで使います。大きなボタンと文字、明るいブルーと黄色、軽い紙吹雪やキャラクターの動きを使っています。

想定 URL：<https://syukie730-coder.github.io/salary-notebook/>

## できること

- iPhone のカメラ撮影・写真ライブラリからの選択。
- 日本語の給与明細を無料の Tesseract.js で端末内読み取り。
- 支給年月と 30 項目を読み取り対象にし、間違った数字は確認画面で修正。
- 保存済みの明細・写真の表示、内容の修正、確認してから削除。
- 年ごとの総支給・控除・手取りグラフ、年間合計、月平均手取り。
- 過去の明細との比較による「今月のひとこと」。外部 AI は使いません。
- 写真を含むバックアップ保存と復元。
- iPhone ホーム画面から単独のアプリのように開くための PWA 設定。

1 か月につき 1 枚を保存します。同じ月を保存するときは、確認のうえで置き換えます。復元では、すでにある同じ月・同じ記録をスキップし、重複登録や上書きをしません。毎月の給与と賞与を同じ月の別明細として保存する構成ではありません。

## 読み取り結果の確認

支給年月、基本給、支給合計、控除合計、振込支給額を大きく表示します。**年月・支給合計・控除合計・振込支給額は、元の写真と見比べてから保存してください。** 金額のつじつまが合わない場合も確認を表示します。読み取り結果を確認なしで保存することはありません。

明細の様式、影、ぼけ、文字の大きさ、傾きによって、項目が空欄になったり、別の数字として読み取られたりします。全項目を必ず認識できる保証はありません。読み取り時は写真の向きを補正し、主要項目が不足した場合は端末内でグレースケール化・明るさとコントラストの調整を行って表向けに再読取します。動作確認は個人情報を含まない合成の見本を使用しており、ご本人の実際の給与明細の様式での認識は未確認です。読み取れない場合は、明るい場所で文字を横向きにして撮り直すか、確認画面で修正します。

対象は支給年月に加え、勤務 6 項目、支給 13 項目、控除 9 項目、手取り 2 項目の計 30 項目です。細かな項目は「その他の読み取り項目」を開いて確認できます。

## 保存・プライバシー・通信

- 給与データと写真はブラウザの IndexedDB（端末内の保存領域）に保管します。給与明細を外部サーバーへ送信しません。
- サーバー処理、外部データベース、有料 OCR、外部 AI API、API キー、自動課金はありません。
- 初回の読み取りでは、アプリと同じサイトから無料 OCR の実行ファイル・日本語と英語の学習データを約 8 MB 取得します。これはプログラムのダウンロードであり、写真のアップロードではありません。
- 読み取りに使用したファイルは Service Worker（オフライン用の保存処理）がキャッシュします。必要なファイルの取得が完了しキャッシュが残っていれば、その後はオフラインでも読み取れます。初回は通信できる状態で使います。
- キャッシュやブラウザの保存データが消去された場合は、再ダウンロードやバックアップからの復元が必要です。端末変更、Safari と別のブラウザ、ローカル確認用 URL と公開 URL の間で記録は自動移動しません。
- 定期的に「バックアップを保存」を使ってください。バックアップには写真と給与の数字が含まれるため、自分だけが見られる場所に保管します。給与明細やバックアップをこのリポジトリに追加しないでください。
- GitHub Pages に置くのはアプリのファイルだけです。訪問者が保存した給与データが公開リポジトリに追加されることはありません。

写真は保存前に長辺最大 2,000 px に縮小し、WebP・品質 0.88 を優先して圧縮します。WebP を作れない環境では JPEG を使用し、1.5 MB を超える場合は品質 0.78 で再圧縮します。元の写真ライブラリの画像は変更しません。

`index.html` の CSP（読み込み先を制限する設定）は、スクリプト・通信を同一オリジンに制限しています。外部の OCR サービスや CDN を実行時に使用しないため、必要なファイルとライセンスを `vendor/` に同梱しています。詳細は [vendor/README.md](vendor/README.md) を参照してください。

## GitHub Pages とローカル確認

ビルド不要の HTML / CSS / JavaScript です。GitHub Pages は公開リポジトリの `main` ブランチ・`/ (root)` を公開元にします。すべて相対パスで読み込むため、`/salary-notebook/` のようなサブディレクトリでも動きます。`.nojekyll` も同梱しています。

ローカル確認用のサーバーは、このフォルダで起動します。

```sh
python3 -m http.server 8768 --bind 127.0.0.1
```

確認 URL は `http://127.0.0.1:8768/` です。PWA の機能は HTTPS または localhost で使用します。iPhone からは GitHub Pages の HTTPS の URL を Safari で開く構成です。

## 画像・アイコンを差し替える場所

| ファイル | 用途 |
| --- | --- |
| `assets/mascot.svg` | ホーム画面と保存後に使う作業服の男性キャラクター |
| `assets/apple-touch-icon.png` | iPhone ホーム画面用・180 × 180 px |
| `assets/icon-192.png` | PWA 用・192 × 192 px |
| `assets/icon-512.png` | PWA 用・512 × 512 px |
| `assets/icon.svg` | 現在のアイコンの元デザイン |

同じ名前・形式で差し替えられます。SVG の元デザインを変更しただけでは PNG は更新されないため、3 サイズの PNG も作成してください。画像を縦横に引き伸ばさず、四隅のマスクに隠れて困る文字や顔は中央寄りに配置します。

アプリを更新して配布する際は `sw.js` のキャッシュ名のバージョンも更新します。iPhone のホーム画面アイコンが古いままの場合は、Safari 側で新しい画像を読み込んだ後、ホーム画面への追加をやり直す必要があります。ブラウザの記録消去はアイコン更新のために行わないでください。

## 開発時の確認

Node.js がある環境で読み取り解析のテストを実行できます。

```sh
node tests/parser.test.cjs
node tests/table-ocr.cjs
```

ブラウザを使った通し確認は、ローカルサーバーを起動した状態で行います。

```sh
node tests/smoke.cjs
```

`tests/smoke.cjs` はこの作業環境にある Playwright と Chrome を使用します。別の開発環境では冒頭の Playwright の参照先を調整してください。これらは開発用テストであり、アプリを使うために Node.js や Playwright を導入する必要はありません。

テストでは合成の給与明細を使い、実 OCR、項目名と金額の位置対応、分割されたカンマ付き金額、傾きと明るさのむら、数字の修正と保存、一覧・再読込後の永続保存、グラフ、写真の圧縮、バックアップの保存・復元と重複防止、不正ファイルによる途中変更の防止、削除の確認とキャンセル、幅 320 / 390 / 430 px、オフライン OCR、外部への通信・アップロードがないことを検証します。実機の iPhone のカメラ、Safari の操作、ホーム画面追加は実機での確認が必要です。
